# Внешняя обработка "Анализ ведомостей"

**Версия:** 1.0  
**Платформа:** 1С:Предприятие 8.3.25 (управляемые формы)  
**Конфигурация:** любая, содержащая описанные в задании объекты метаданных

## Описание

Внешняя обработка предназначена для анализа документов «Ведомость» на основе данных справочника «Договоры» и регистра сведений «ИсторияСтатусовДокументов».

### Основной функционал

#### Команда «Заполнить нужное»
- Фильтрует ведомости по условию:
  - Дата начала действия *первого активного договора* в табличной части ведомости **равна** или **не равна**
  - **Минимальной** или **максимальной** дате начала действия договора в этой табличной части.
- Дополнительное исключение ведомостей в зависимости от числа (дня) текущей даты (см. таблицу исключений).
- Выводит отфильтрованные ведомости в таблицу, упорядоченные по возрастанию даты документа.
- Выделяет светло-зелёным цветом строки, у которых последний статус в регистре сведений = «Акцептован».

#### Команда «Удалить лишнее»
- Удаляет из отображённой таблицы строки, у которых количество договоров в табличной части документа **чётное**.
- Выводит информацию об удалённых документах в формате:
  > Удалено документов: X (номер1, номер2, …)
- Способ вывода информации зависит от **длины фамилии кандидата** (настраивается пользователем).

## Дополнительный функционал (динамические условия)

### 1. Исключение ведомостей при заполнении таблицы
В зависимости от дня **даты отправки решения** (задаётся пользователем):

| Диапазон | Исключаются ведомости |
|----------|------------------------|
| 1–10 число | у которых день даты ведомости **равен** числу текущей даты |
| 11–20 число | у которых день даты ведомости **чётный** |
| 21–31 число | у которых месяц даты ведомости **нечётный** |

### 2. Способ создания условного оформления
На форме есть переключатель **«Пол кандидата»**:
- **Женский** – условное оформление создаётся интерактивно (имитация конструктора формы)
- **Мужской** – условное оформление создаётся программно

Оба варианта дают одинаковый визуальный эффект (светло-зелёный фон для строк со статусом «Акцептован»).

### 3. Способ вывода информации об удалении
Зависит от **длины фамилии кандидата** (поле ввода):

| Длина фамилии | Способ вывода |
|---------------|----------------|
| < 6           | `Сообщить()` |
| 6–7           | Объект `СообщениеПользователю` |
| 8–9           | Открытие произвольной формы с текстом |
| 10–11         | Вывод в элемент основной формы (надпись) |
| 12–13         | Вызов исключения |
| > 13          | `ПоказатьПредупреждение()` |

## Установка и использование

### Требования к конфигурации базы данных
В информационной базе должны присутствовать следующие объекты (см. «Исходные данные»):

- Перечисление **«СтатусыДокументов»** со значениями: Создан, Внутренний, Акцептован, Заблокирован.
- Справочник **«Договоры»** с реквизитами: Наименование, Активен, НачалоДействия.
- Документ **«Ведомость»** с табличной частью «Договоры», содержащей реквизит «Договор» (ссылка на справочник Договоры).
- Регистр сведений **«ИсторияСтатусовДокументов»** (независимый, непериодический) с измерениями: ДатаЗаписи, Документ (составной, включая Ведомость), Статус (ссылка на перечисление).

### Установка внешней обработки
1. Скачайте файл `АнализВедомостей.epf`.
2. В 1С:Предприятии откройте нужную базу в режиме «Предприятие».
3. Выберите меню **Файл → Открыть** или используйте команду «Открыть» на панели инструментов.
4. Укажите путь к файлу `АнализВедомостей.epf`.
5. Обработка откроется в отдельном окне.

### Параметры работы

Перед нажатием команд настройте параметры:

- **Операция сравнения** – «Равно» или «Не равно».
- **Тип даты** – «Минимальная» или «Максимальная».
- **Дата отправки решения** – дата, влияющая на исключение ведомостей (по умолчанию текущая).
- **Пол кандидата** – «Женский» или «Мужской» (определяет способ создания условного оформления).
- **Фамилия кандидата** – строка, влияющая на вывод сообщений после удаления.

### Пример использования

#### Пример 1
- Условия: «Равно», «Минимальная»
- Дата отправки решения = 15 число (11–20 → исключаются чётные дни ведомостей)
- Пол кандидата = «Женский», фамилия = «Иванова» (длина 7 → сообщение через `СообщениеПользователю`)

После нажатия **«Заполнить нужное»** в таблице появятся ведомости, удовлетворяющие условию.  
После нажатия **«Удалить лишнее»** из таблицы удалятся строки с чётным числом договоров, а пользователь увидит сообщение в отдельном окне (т.к. длина фамилии 7).

#### Пример 2
- Условия: «Не равно», «Максимальная»
- Дата отправки = 25 число (21–31 → исключаются ведомости с нечётным месяцем)
- Пол = «Мужской», фамилия = «Петров» (длина 6 → сообщение через `СообщениеПользователю`)

Цветовое выделение будет работать одинаково, но создано программно.

## Примечания для разработчиков

- Код модуля формы написан с разделением контекста выполнения (`&НаСервере`, `&НаКлиенте`) для оптимальной производительности.
- Основной отбор ведомостей выполняется одним запросом к СУБД.
- Для получения последнего статуса используется подзапрос с `МАКСИМУМ` – это быстрее, чем выборка всех записей регистра.
- Условное оформление при выборе «Женский» создаётся один раз при создании формы (имитация интерактивного), а при выборе «Мужской» – программно при изменении переключателя.
- Подсчёт количества договоров при удалении можно оптимизировать, объединив в один запрос, но для наглядности оставлен цикл с запросом по каждому документу.

## Возможные доработки

- Добавить индикатор прогресса при большом количестве ведомостей.

- Реализовать возможность сохранения настроек (пол, фамилия) между сеансами.
